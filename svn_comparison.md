# Git и SVN

## 1. Почему в Git ветвление «дешёвое», а в SVN «дорогое»?
В Git ветка это указатель на коммит, а не копия файлов, поэтому создать ветку значит создать новый указатель размером в несколько байт. Операция локальная и мгновенная, копировать содержимое репозитория не нужно. В SVN ветка это директория внутри дерева репозитория (`/branches/имя-ветки`), которую создают командой `svn copy`. Создание ветки идёт на сервере и требует сетевого запроса. Также и слияние в svn сложнее, оно хуже отслеживает переименования и параллельные изменения файлов, поэтому  ветвление и merge в svn получаются медленнее и рискованнее 

## 2. Можно ли в SVN сделать коммит без интернета?
Нет. SVN централизованная система контроля версий, где есть один сервер с репозиторием, а у разработчика локально лежит только рабочая копия без полной истории проекта


## 3. Когда SVN может быть предпочтительнее Git?
- **Большие бинарные репозитории.** SVN умеет частично выгружать дерево (`svn checkout` только нужной папки) и не тянет всю историю проекта. Это полезно, когда в репозитории много тяжёлых бинарных файлов, например ассеты в игровых студиях или CAD-проекты
- **Централизованный доступ.** Весь код лежит на одном сервере, поэтому проще настроить права доступа отдельно для каждой папки и группы пользователей. Это удобно в крупных компаниях со строгими требованиями к безопасности
- **Простая линейная модель.** Если команда не ветвится активно и привыкла к схеме «один центральный сервер один источник правды», SVN проще понять и администрировать, чем распределённую модель Git
- **Legacy-инфраструктура.** Часть старых корпоративных проектов уже построена вокруг SVN
